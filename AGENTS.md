- Все новые сайты АГК создаются здесь в `sites/<slug>/`, регистрируются в `sites.json` и открываются по `/<slug>/` на COM и RU доменах.
- Не создавать отдельные GitHub-репозитории, COM-копии или долгоживущие RU/COM-ветки. Общие дизайн и тексты — один исходник; виджеты и другие региональные настройки — в конфигурации editions.
- Основная ветка `main`. COM: Vercel, `npm run build:com`, `dist/com`. RU: Beget, `npm run build:ru`, `dist/ru`.
- Root Directory Vercel — корень репозитория, не `sites/clients` и не `agk-webinar-com`.
- RU: исходный архив rsya-main размещён без изменений в `sites/rsya-ru`, копируется в корень только RU-сборки через `static-roots.json`. Сохранить `/`, `/max/`, `/psy/` и `.htaccess` побайтово, если пользователь не просит изменений. COM не получает эти файлы и пока не имеет главной. Не переименовывать существующие адреса.
- Текущий вебинар — `/clients/`, COM-виджет 1656005, RU-виджет 1655985. После успешной регистрации GetCourse должен направлять на `/thanks/` (COM) или `/spasibo/` (RU). Внешние настройки и тестовые заявки требуют отдельного разрешения.
- Платный шахматный мастер-класс — `/mkclients/`, исходник `sites/mkclients`; он публикуется в обеих сборках без отдельных копий и без собственных страниц благодарности.
- Новым вебинарам давать уникальные страницы благодарности или вложенные адреса; не перезаписывать существующие root aliases.
- `/sales/`: COM-виджет1670561 → `/sales/thanks/`, RU-виджет1670558 → `/sales/spasibo/` (RU-only alias существующей thanks). Проверять существование точного адреса из GetCourse в региональной сборке и HTTP-ответ после загрузки; настройка data-success-path не управляет внешним редиректом виджета.
- `/sales/`: изолированная `/sales/registration/` должна получать query родительской страницы до запуска официального скрипта GetCourse. Сохранять синхронный порядок `registration-context.js` перед виджетом и метки в резервных ссылках обеих форм. Проверять параметры реального запроса GetCourse на RU/COM, а не только URL лендинга; не отправлять тестовые заявки без отдельного разрешения.
- Проверять обе сборки, пути ресурсов в подпапках и мобильную вёрстку. Не коммитить dist, node_modules, секреты и локальные отчёты.
- Использовать apply_patch. Сохранять пользовательские изменения и не отправлять заявки при проверке виджета.
- Новые страницы собирать поблочно: карта исходного ТЗ, конкретная роль каждого референса, единая утверждённая система AGK. Юридическую техническую передачу проверять по Website Rules Pack/checklists/LEGAL_HANDOFF.md; неполученные ссылки оплаты/оферты не угадывать.
- В основных CTA текст оптически центрирован и не сдвигается стрелкой: иконка закрепляется у правого края независимо. Для крупных CTA использовать читаемый размер текста около 15–16 px; внешний GetCourse submit допускается полноширинным элементом формы, если содержимое iframe нельзя стилизовать из проекта.
- Названия материалов в первом экране дублировать живым читаемым текстом внутри плашек: мелкая надпись на сгенерированной обложке не заменяет подпись. На mobile проверять, что все основные CTA не только одинаковы по размеру, но и стоят на одной оси композиции.
