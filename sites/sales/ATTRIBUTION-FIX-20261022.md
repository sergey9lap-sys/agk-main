# Передача меток регистрации — 22.10.2026

## Причина и границы

На действующих COM и RU браузерная проверка показала: рекламная ссылка `/sales/?utm_source=...` сохраняет метки, но обе изолированные страницы `/sales/registration/` открываются без query. Официальный скрипт GetCourse создаёт свой iframe из `window.location.search` промежуточного документа; в его запросе нет самостоятельных UTM-параметров, а `loc` также указывает на адрес без меток. Наличие меток внутри `ref` не заменяет штатную передачу query. Резервная ссылка открытия формы также была без меток.

Источник контракта: публичный скрипт `https://agkedu.getcourse.ru/pl/lite/widget/script?id=1670561` и официальная справка `https://getcourse.ru/blog/275829`. Сетевые URL до/после и результаты браузерных проверок сохраняются локально в `output/sales-attribution-qa-results.json`; там только искусственные диагностические метки.

## Исправление

- Синхронный `registration-context.js` перед официальным скриптом переносит query same-origin родителя в URL промежуточного документа через `history.replaceState`. Внешний вид, маршрут и hash не меняются; перезагрузка формы не нужна. К моменту создания iframe GetCourse метки уже доступны.
- Сохраняется вся строка параметров, включая кодирование, пустые/повторные значения, UTM и параметры рекламных переходов. Нет выдуманного источника, сохранения меток в cookies/localStorage или изменения согласий на аналитику.
- При самостоятельном открытии формы её query сохраняется. Чужой/inaccessible родитель игнорируется. Старый query дочерней страницы не подменяет текущую кампанию родителя.
- Обе резервные ссылки получают тот же query; региональные IDs, размеры, lazy loading и проверки origin/source сообщений высоты сохранены.

Карта сохранности: hero-форма → та же hero-форма; финальная форма → та же финальная форма; резервные ссылки → те же адреса с query; все тексты, медиа, согласия, счётчики, региональные редиректы и остальные разделы без изменений.

## Проверка и выпуск

Сборки `node scripts/build.mjs com` и `node scripts/build.mjs ru`; полный набор `npm test`. Добавлены регрессионные тесты порядка загрузки, меток/кириллицы/спецсимволов, самостоятельного открытия, чужого parent и резервных ссылок.

Обе сборки выполнены, все 27 тестов прошли. Реальный браузер Edge: на действующих RU/COM воспроизведено отсутствие query у GetCourse; на исправленных сборках проверены обе формы при 390 и 1280px. Все пять UTM и yclid присутствуют непосредственно в GET-запросах официальных виджетов1670558/1670561 и в их `loc`; кодирование сохранено. По два запроса на страницу, ошибок JS нет. Размеры форм: 340×517px на mobile, 430×445px на desktop. Все POST-запросы в браузерной проверке блокировались, регистраций не отправляли.

Для RU/Beget подготовить архив только трёх файлов с сохранением каталогов: `sales/registration/index.html`, `sales/registration-context.js`, `sales/registration-host.js`. Сначала загрузить новый JS, затем HTML и host JS; при наличии CDN очистить кэш этих файлов. COM использует обычную публикацию из main. Изменение кода и локальный тест не означают обновление действующих сайтов.

После публикации проверить две формы на обоих доменах по ссылке с тестовыми метками. Передачу query в запрос iframe можно проверить без заявки. Сохранение источника в карточке пользователя/заказа подтверждает только отдельно согласованная тестовая регистрация с техспециалистом. Диагностика не отправляет заявки и не меняет настройки GetCourse.
